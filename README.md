# 看球帳本：私人棒球觀賽管理 APP

給 3～4 位固定朋友共用的手機網頁 APP（可加到 iPhone 主畫面）：賽程、購票訂單、逐張票券、分票取票、付款退款、跨場次結算、比分與個人到場戰績、匯出備份還原。

---

## 1. 已實作的功能

**帳號與權限**
- 首次開啟自動進入「首次設定」，建立第一位管理者與私人群組；之後由管理者新增成員（帳號＋初始密碼，本人登入後可改密碼）。
- 每人獨立帳號、密碼以 bcrypt 雜湊、登入失敗 5 次鎖定 15 分鐘、工作階段存在資料庫（HttpOnly Cookie）。
- 所有權限都在伺服器端檢查；群組資料互相隔離，改網址 ID 也讀不到別的群組。
- 管理者：新增／停用成員（不刪除，帳目保留）、調整權限、重設密碼、修正官方比分、完整備份與還原。
- 重要操作寫入修改紀錄（AuditLog）。

**賽程與比賽**
- 中華職棒官網賽程自動同步（見第 3 節）、管理者貼上官網 JSON 匯入、任何成員 CSV 匯入、手動新增比賽。
- 球隊、球場為獨立資料，預先建立中職 6 隊與 11 座球場，可自行新增。
- 列表與月曆兩種檢視；依球隊、球場、成員、狀態篩選；「只看有買票」。
- 狀態：尚未開賽、進行中、比賽結束、延期、取消、保留比賽、其他；全部以文字標示，不只靠顏色。
- 比分為獨立欄位；只有「比賽結束＋正式確認」才計入勝敗。
- 比賽異動（時間、球場、狀態、比分）都留紀錄並在首頁提醒有買票的人。

**購票訂單與票券**
- 從賽程選比賽直接帶入日期、時間、球隊、球場；一次建立多張票，「依序分給每人」、「連號座位快速填寫」。
- 即時分攤預覽；手續費分攤四種方式（購票人吸收／持票人平均／按票數／自訂），零頭一律由購票人吸收，總額必定相符。
- 每張票獨立管理：持有人、座位、類型、取票方式、分票狀態、取票狀態、持有人確認收到、票券識別資訊（條碼／序號／連結僅購票人、持有人、管理者可見）。
- 「已指定」「已交付」「已取票」「已付款」互不自動代替。
- 取消、退票、移除票券都不刪資料；移除的票其已付款會顯示為「需退回」。
- 「前往售票平台」：有平台官方 App 連結才顯示「開啟售票 App」，否則開 HTTPS 網頁；可「檢查連結」；不登入、不存任何售票帳密。

**付款、退款、結算（金額全部以整數元儲存）**
- 每筆訂單上，每位持票人對購票人的「應付／已付／尚欠／狀態」由紀錄即時計算（未付款、部分付款、已付清、溢付待退款、已退款）。
- 付款可分次；付款人與收款人各自確認，不能替對方確認；撤銷保留紀錄，對方已確認的只能由管理者撤銷。
- 朋友間退款（例如退票後退回已付的錢）與售票平台退款（紀錄用）。
- 結算：跨場次彙總兩人之間的淨額，建立結算紀錄與一筆淨額付款，原始帳目完整保留；可取消結算。
- 防重複：每個表單有一次性請求 ID（雙擊不會重複）、群組層級交易鎖（多人同時付款不會超付）、樂觀鎖（同時修改同一筆會提示重新整理）、畫面金額過期時結算會被拒絕。
- 修改票價、費用或分攤時，舊應付紀錄作廢保留、產生新紀錄，歷史可核對。

**比賽結果與統計**
- 每位成員每場可記錄「已到場／預計到場／沒去」與支持球隊（只能選本場參賽球隊）；拿到票時自動預設為最支持的球隊。
- 個人到場戰績：勝、敗、和、勝率（勝 ÷（勝＋敗），和局不列入）、主場／客場、各支持球隊、最常看的球隊與球場、一起到場次數、觀賽歷史。
- 球隊正式賽季戰績另外一頁，與個人到場戰績分開。
- 比分被更正時統計自動重算（統計不存結果，每次由比賽資料計算，不會重複計入）。
- 花費：個人負擔、購票支出、代墊、尚未收回、已收回、每月、各球隊、各球場、單場平均。三者定義分開並在畫面上說明。

**首頁與提醒（APP 內）**
- 今日比賽、我的下一場、未來 7 天有買票的比賽、待辦事項（未分配、未交付、待確認收到、未取票、取票期限、我要付、別人欠我、溢付需退款、退款處理中、待確認付款、到場確認、賽程異動、即將開賽），每一項都有「處理」連結直達頁面。

**匯出、備份、還原**
- CSV（8 種資料，含指定購票期間）與 Excel（全部分頁）；每列保留訂單、票券、比賽、結算 ID；CSV 防公式注入。
- 管理者下載完整 JSON 備份；還原前驗證格式、內部關聯、重複 ID、成員對應，顯示「目前 vs 備份」筆數，需輸入「確認還原」；還原在單一交易內完成，並自動保存還原前快照。

## 2. 技術架構

| 項目 | 選擇 |
|---|---|
| 前後端 | Next.js 15（App Router、Server Actions）＋ TypeScript |
| 介面 | Tailwind CSS 4，手機優先，可加到主畫面（PWA manifest） |
| 資料庫 | PostgreSQL ＋ Prisma 6（外鍵、唯一限制、索引、交易） |
| 驗證 | Zod（訊息使用繁體中文） |
| 測試 | Vitest（單元、整合，使用真實 PostgreSQL）、Playwright（端對端） |
| 部署 | Vercel（免費方案）＋ Neon PostgreSQL（免費方案） |

程式結構：
- `src/server/services/*`：所有商業邏輯與權限檢查（頁面與 API 只呼叫這一層）
- `src/lib/money.ts`：分攤演算法；`src/lib/results.ts`：勝敗判定；`src/lib/sync/cpbl.ts`：官網資料解析
- `src/server/services/schedule.ts`：賽程同步服務（獨立，不碰任何購票資料）
- `prisma/schema.prisma`：資料模型（User、Group、GroupMember、Team、Venue、Game、GameChange、GameAttendance、TicketPlatform、TicketOrder、Ticket、TicketTransfer、Obligation、Payment、Refund、Settlement、SettlementItem、PaymentMethod、ScheduleSyncLog、AuditLog）

## 3. 賽程資料來源與限制（請務必閱讀）

**實際來源**：中華職棒官網賽程頁 <https://www.cpbl.com.tw/schedule>。
2026-10-12 我在你的電腦瀏覽器中實際檢查：該頁以 `POST /schedule/getgamedatas` 取得 JSON（參數 `calendar`、`kindCode`、`location`、`teamNo`），需要頁面內嵌的 `RequestVerificationToken` 與同一次請求取得的 Cookie。沒有公開文件、沒有 API 金鑰。

**實作方式**：同步服務先讀賽程頁取得驗證資訊，再取 JSON，嚴格驗證欄位後才寫入。已處理官網的實際資料特性：同一場次會因延賽、保留比賽出現多列（例如 2026 例行賽第 14 場延賽兩次後於 10/5 完賽），系統合併為一場並以官網場次編號辨識，不會重複。主客隊、比分一律依官網欄位（`HomeTeam*`、`VisitingTeam*`）。

**已驗證範圍**：解析邏輯用 2026-10-12 從官網實際取得的資料（例行賽樣本＋完整季後挑戰賽）做測試；完整同步流程（含驗證資訊與 Cookie）用模擬官網回應測試。

**尚未驗證**：我的開發環境無法從伺服器端連到官網，所以「部署後的伺服器能否直接連上官網」還沒實測。部署後請在「賽事」頁按「立即同步」確認；若失敗，畫面會顯示原因，既有賽程不受影響。替代方案：管理者在「匯入賽程」貼上官網 JSON（頁面有步驟說明），或用 CSV 匯入。

**其他限制**：
- 這是官網內部使用的介面，不是正式 API，官網改版可能失效；失效時同步會失敗並記錄原因，不會寫入錯誤資料。
- 賽程資料版權屬中華職棒；本 APP 僅私人使用，排程每天只同步一次，手動同步至少間隔 3 分鐘。
- Vercel 免費方案的排程每天只能執行一次（設定為每天台灣時間 23:40 左右，用來更新當天比分）；比賽中需要即時比分請按「立即同步」。

## 4. 環境變數

| 名稱 | 必填 | 說明 |
|---|---|---|
| `DATABASE_URL` | 是 | PostgreSQL 連線字串（Neon 用 pooled 網址） |
| `DIRECT_URL` | 是 | 執行遷移用的直連網址（Neon 用非 pooled 網址；本機與上面相同） |
| `CRON_SECRET` | 是 | 排程同步密鑰，任意 32 字以上亂碼；Vercel Cron 會自動帶上 |
| `SYNC_KIND_CODES` | 否 | 同步的賽事類型，預設 `A,E,C`（例行賽、季後挑戰賽、總冠軍賽） |

所有密鑰只在伺服器端使用，沒有任何 `NEXT_PUBLIC_` 變數。範本見 `.env.example`。

## 7. 尚未完成的功能與原因

- **推播通知**：未做。第一版依需求只做 APP 內待辦與提醒。iPhone 網頁推播需加到主畫面並另外處理 Web Push 訂閱，雖可免費，但會增加維護成本，建議實際使用一陣子後再決定。
- **伺服器直連官網的同步**：程式已完成，但需部署後實測（見第 3 節）。
- **售票平台 App 跳轉**：預設平台只填官方網站網址。若某平台有官方公布的 App 連結，可在「個人 > 售票平台」自行新增；我沒有替任何平台假設 App 連結格式。
- **離線使用**：沒有做離線快取（避免私密票券資料留在手機快取）；沒網路時會明確提示「資料尚未儲存」。

## 8. 部署方式（GitHub → Vercel → Neon，全部免費方案）

1. **Neon**：建立專案（區域建議 Singapore），複製兩個連線字串：pooled → `DATABASE_URL`、direct → `DIRECT_URL`。
2. **GitHub**：建立儲存庫並上傳此專案（`.env` 已在 `.gitignore`，不會上傳）。
3. **Vercel**：Import 該儲存庫，在 Environment Variables 填入第 4 節的變數，部署。
4. **建立資料表**：在自己電腦的專案資料夾，把 `.env` 換成 Neon 的連線字串後執行 `npx prisma migrate deploy` 與 `npm run db:seed`（只需一次；之後有新遷移再執行）。
5. 開啟 Vercel 網址 → 首次設定 → 新增 3 位朋友 → 在「賽事」按「立即同步」確認官網同步。
6. iPhone：用 Safari 開網址 →「分享」→「加入主畫面」。

`vercel.json` 已設定排程與 Singapore 區域。免費方案限制：Vercel 排程每天一次；Neon 免費資料庫閒置會休眠，第一次開啟可能慢 1～2 秒。

## 9. 備份與還原

- **APP 內**：管理者在「個人 > 資料匯出、備份與還原」下載完整備份（JSON）；建議每月或每次大量結算後下載一次，存在私人雲端。檔案含票券序號，請勿公開分享。
- **還原**：同一頁上傳備份 → 檢查結果 → 輸入「確認還原」。還原會取代本群組的訂單、票券、付款、退款、結算與觀賽紀錄；官方賽程不受影響；還原前的資料會自動保存在修改紀錄中。備份中的帳號必須已存在於系統（以帳號名稱對應）。
- **資料庫層級**：Neon 免費方案提供短期時間點還原；也可用 `pg_dump "$DIRECT_URL" > backup.sql` 自行備份。

## 10. 已知限制與後續建議

- 官方賽程（全站共用）的比分只有管理者能手動修正；手動修正後預設「鎖定」，之後同步不覆蓋，需要時可取消勾選。
- 球隊與球場是全站共用資料（不含任何私人資訊）。
- 結算是「兩人之間」的淨額；三人以上的循環抵銷（A 欠 B、B 欠 C、C 欠 A）目前需逐對結算。
- 售票平台退款只做紀錄，朋友間帳目以票券「已退票」或訂單「已退款」狀態為準；退票後手續費是否退回請以自訂分攤或修改費用處理。
- 建議：實際使用 2～4 週後，再決定是否加入推播、三人循環抵銷與更多報表。
